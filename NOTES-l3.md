Варіант

Журнал: 7, варіант: 7, прізвище: Бурлаченко

1\. stash list

```
stash@{0}: On lab3/variant-7-burlachenko: чернетка нотатки v7
```

Я сховав зміни в NOTES.md і новий файл draft-v7.txt командою `git stash push -u -m`. Прапорець `-u` потрібен, щоб сховався і новий файл, а `-m` дає запису своє ім'я в списку.

2\. cherry-pick

```
69d0d39 (HEAD -> feature/pick-7) Додати пояснення гілки
47f8a0d cherry-pick: Додати пояснення гілки
```

Перший хеш (69d0d39) — коміт на гілці feature/pick-7, другий (47f8a0d) — його копія на гілці lab3. Хеші різні, бо cherry-pick не переносить сам коміт, а створює новий із копією патча.

3\. reflog

```
47f8a0d HEAD@{1}: cherry-pick: Додати пояснення гілки
1996044 HEAD@{0}: commit (amend): Уточнити пояснення гілки, варіант 7
```

До amend на гілці був коміт 47f8a0d, після amend його замінив коміт 1996044. Старий хеш не зник, його видно в reflog.

4\. revert

```
7f9ec4e (HEAD -> lab3/variant-7-burlachenko, origin/lab3/variant-7-burlachenko) Revert "Зіпсувати рядок"
c76f4b0 Зіпсувати рядок
1996044 Уточнити пояснення гілки, варіант 7
7497007 Додати чернетку v7
0a5c9c2 Додати NOTES.md
```

Поганий коміт «Зіпсувати рядок» вже був запушений, тому я не стирав його, а скасував новим комітом через `git revert`. В історії видно обидва коміти, а на кінчику гілки поганого рядка вже немає.

5\. тег

```
tag v0.1-burlachenko
Tagger: mister-vite <danivicdana@gmail.com>
Date:   Tue Oct 13 19:11:11 2026 +0200

Перший зріз варіанта 7
```

Тег створений з прапорцем `-a`, тому він анотований: у ньому є автор (Tagger), дата і повідомлення. Після створення я запушив його в origin.

6\. rebase -i

```
pick  WIP: чернетка
squash fix typo
```

Підсумкове повідомлення: `Пояснити особисту гілку`

Я зробив `git rebase -i HEAD\~2`: у першому рядку залишив pick, у другому поставив squash, і два коміти склеїлися в один. Після цього запушив гілку командою `git push --force-with-lease`, тільки на свою гілку.

7\. blame

```
19960444 (mister-vite 2026-10-13 18:41:57 +0200 4) Гілка feature/docs-v7 для окремої правки
```

`git blame` показує для кожного рядка, у якому коміті, ким і коли він востаннє змінювався. Цей рядок прийшов через cherry-pick і був змінений при amend, тому в blame видно хеш після amend.

8\. fork

origin — це мій форк на GitHub, upstream — оригінальний репозиторій.
Свіжі зміни з оригіналу я забираю командою `git fetch upstream`.
Свої коміти я пушу в origin.
Pull Request відкриваю з мого origin в upstream/main.
